# Chat / Cowork / Code の段階設計

| 入口 | 利用者が行うこと | 次の実装 |
| --- | --- | --- |
| Chat | モデルとの会話、履歴、分岐 | 会話単位のコンテキストと利用枠を拡張 (#68) |
| Cowork | 資料整理、組み込みツール、連携管理 | 作業セッションと手動で許可した読み取り専用連携 (#27, #84) |
| Code | リポジトリを選び、変更案やテスト結果を確認 | 読み取り専用のリポジトリ選択から始め、隔離ランナーを別段階で導入 (#84) |

ホームはプロフィール・料金・実績の入口。今回の Cowork は専用 URL とナビゲーションを持ち、既存の Chat と連携機能を呼び出す。独立した作業セッションは次段階で追加する。

共通セッションに owner、mode、resource scope、状態、作成日時を保持する。実行記録には親子関係、処理状態、利用量、停止理由を持たせる (#67)。停止は子にも伝播させ、並列数と予算をサーバーで制限する。推論には既存の Cost Gate を使う。料金集計と将来のトークン上限は別に扱う (#68)。

外部 MCP は接続先を管理側で承認し、利用者の権限でツール一覧を読み取るところから始める。ツール呼び出し、外部送信、書き込みは権限を個別に確認する。プラグイン定義はバージョン固定し、登録時に権限を付与しない (#27, #19)。

Code は対象リポジトリを明示選択し、作業単位の隔離環境と短命の権限で運用する。変更は差分で提示し、公開・マージは人間が承認する。先にデータ境界、ランナー費用、キャンセルと削除の手順を確定する。自動の脆弱性悪用・侵入を実行するツールは対象外。
